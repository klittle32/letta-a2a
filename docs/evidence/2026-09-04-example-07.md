# Example 07 evidence — 2026-09-04

This is the concise execution record for [OAuth client credentials](../../examples/07-oauth-client-credentials/).

## Implemented boundary

- A local Starlette authorization server exposes RFC 8414-style metadata, a client-credentials token endpoint, and an ephemeral RSA JWKS.
- The bridge and Python reference agent exchange client credentials, cache short-lived access tokens, and refresh near expiry.
- Agentgateway v1.5.0 validates JWT signature, issuer, audience, expiry/not-before, and subject. A separate authorization rule requires membership of `a2a.invoke` in the token's space-delimited scopes.
- Both canonical A2A 1.0 Agent Cards advertise the OAuth2 client-credentials flow, metadata URL, token URL, and required scope.
- The smoke and integration clients obtain access tokens instead of reading a static gateway token.

The valid JSON-RPC authentication probe reached the backend and returned the expected task-not-found A2A envelope with HTTP `200`.

The first expiry probe checked a token immediately after its six-second `exp` and agentgateway still accepted it, consistent with normal JWT clock-skew tolerance. The deterministic test was corrected to use a separately registered, integration-only stale client whose token is already five minutes beyond expiry. No claim is made about the gateway's exact leeway duration.

## Scope boundary

The current `a2a.invoke` rule is intentionally universal. Every ordinary lab caller uses the same client identity, so this stage proves cryptographic authentication and one required scope—not per-caller authorization. That distinction remains the purpose of Example 08.
