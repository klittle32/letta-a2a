## Provider-free protocol proof

The deterministic suite proved:

1. The gateway-published reference-agent card advertises `pushNotifications: true`.
2. The receiver rejects missing and incorrect callback Bearer credentials with `401`; its observation endpoint independently rejects missing observer authentication.
3. `SendMessage` registers an inline callback before starting `slow 1` and returns a non-terminal task.
4. A metadata-service callback URL is rejected.
5. `CreateTaskPushNotificationConfig`, `GetTaskPushNotificationConfig`, `ListTaskPushNotificationConfigs`, and `DeleteTaskPushNotificationConfig` work through agentgateway.
6. Get/list responses do not expose the stored callback credential.
7. Two callback registrations deliver the same terminal event twice; the receiver retains one canonical event with `deliveryCount: 2`.
8. The initiating path does not call `GetTask` while the task runs. It waits for the terminal callback first.
9. The later authenticated `GetTask` returns `TASK_STATE_COMPLETED` and artifact text `slept: 1`.
10. The existing authentication, authorization, streaming, disconnect, polling, continuation, failure, cancellation, and log-secret assertions remain green.

## Provider-backed Letta proof

The live suite repeated the callback lifecycle against Letta Agent A. The Letta task explicitly delegated `slow 2` to the reference agent and then returned `LETTA_PUSH_OK`.

The test observed a duplicate-safe terminal callback before calling `GetTask`; the authoritative task was completed with exact artifact text `LETTA_PUSH_OK`. The remainder of the live matrix—safe Letta SSE projection, delegation in both directions, and nested cancellation—also passed.

## Security assertions

- Registration accepts only the exact server-configured callback URL.
- Registration requires exact `Bearer` scheme spelling and the configured credential.
- Legacy `token` authentication is rejected.
- Both senders revalidate configuration before dispatch and refuse redirects.
- Python callback I/O runs outside the SDK event consumer while an explicit per-task chain preserves process-local order.
- Callback payloads use `application/a2a+json`.
- The receiver authenticates callback delivery before JSON parsing, separately authenticates observation reads, bounds request bodies, and accepts one recognizable A2A stream-event variant.
- Callback credentials are redacted from configuration reads and absent from callback observation payloads.
- Service-log scanning includes the receiver and the callback credential.
- Receiver state does not regress from terminal to a later non-terminal event.
- Python ASGI shutdown closes the SDK request handler, cancels pending best-effort callback work, and closes the owned HTTP client.

## Claims intentionally not made

The checks do not prove retries, at-least-once or exactly-once delivery, a durable outbox, persistence across restarts, arbitrary-URL SSRF safety, public HTTPS deployment, cryptographic replay prevention, cross-replica ordering, or production multi-tenant ownership isolation.
