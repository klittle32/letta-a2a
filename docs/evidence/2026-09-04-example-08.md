# Example 08 evidence — 2026-09-04

This is the concise execution record for [authorization policy](../../examples/08-authorization-policy/).

## Implemented boundary

- The local OAuth fixture has distinct operator, bridge, reference-agent, observer, and denied-invoker registrations.
- Tokens contain issuer-controlled `sub`, `client_id`, `role`, and `scope` claims.
- Agentgateway's allowlist permits Agent Card `GET` only with `a2a.discover` and permits A2A JSON-RPC `POST` only with `a2a.invoke` plus an `operator` or `agent` role.
- The bridge and reference agent use dedicated `agent` credentials rather than the shell operator's credentials.
- Both Agent Cards advertise both available scopes while retaining `a2a.invoke` as their top-level A2A security requirement.

## Automated evidence

The provider-free managed matrix observed:

```text
operator + a2a.discover                  Agent Card GET 200
operator without a2a.discover            Agent Card GET 403
observer + a2a.discover                  Agent Card GET 200
observer + a2a.discover                  JSON-RPC POST 403
observer requesting a2a.invoke           token endpoint 400 invalid_scope
untrusted role + a2a.invoke              JSON-RPC POST 403
operator role + a2a.invoke               JSON-RPC POST 200
```

The successful JSON-RPC authorization probe reached the backend and returned an A2A task-not-found envelope with HTTP `200`. The matrix then passed discovery, asynchronous messaging/polling, context continuation, explicit failure, and cancellation under the same policy.

Authentication failures remained distinct:

```text
missing token                            401
malformed compact token                  401
valid issuer with wrong signature        401
token issued five minutes stale          401
invalid OAuth client                     token endpoint 401
```

The provider-backed run additionally verifies both internal service identities through live nested delegation in each direction and outer-to-child cancellation propagation.

## Scope boundary

This example proves caller-aware policy, not production authorization. The local issuer assigns a small custom role claim from fixed in-memory registrations. Every JSON-RPC operation still shares one invocation permission, and no task-level ownership, tenant boundary, revocation system, or durable audit store is claimed.
